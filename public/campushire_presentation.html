Slide 2: Problem Statement & Stakeholder Impact

CRITICAL INSTITUTIONAL PROBLEM

The Operational Bottlenecks

✕ Spreadsheet Chaos & Data Leaks

Campus placement cells manually manage 100+ conflicting Excel spreadsheets, CSVs, and WhatsApp groups, risking data corruption, missing registrations, and privacy breaches.

✕ Manual Eligibility Verification Delays

Manually matching thousands of students against company criteria (CGPA cutoff, active backlogs, branches, 10th/12th percentages) takes 3–5 days per company, causing recruitment delays.

✕ Zero Real-Time Visibility

Students remain anxious without live application tracking; recruiters struggle to track interview pipelines; placement officers have no real-time cohort analytics.

Target Stakeholders & Why It Matters

🎓

Students

Instant eligibility check, 1-click apply, interview calendar.

🏢

Recruiters

Pre-vetted talent, stage kanban, scheduled interview slots.

🏛️

TPO Officers

Dean policy overrides, cohort analytics, live audit logs.

💡 Institutional Importance:

University NIRF/NAAC accreditations and admissions heavily hinge on verified placement percentages. A single verification error can cost a deserving student a life-changing Tier-1 opportunity or damage the university's corporate relationships.

Core REST Endpoints

Method Endpoint Purpose Access
POST /api/auth/login Issue JWT bearer token Public
GET /api/jobs List active drives & roles All Auth

POST /api/applications/:id/override Dean policy exception Admin Only
PATCH /api/applications/:id/status Advance pipeline stage Recruiter/Admin
GET /api/admin/dashboard-stats Live 84% cohort metrics Admin Only

Business Logic & Validation Rules

1. Declarative Eligibility Formula:
isEligible = (student.cgpa >= job.min_cgpa) &&
  (student.backlogs <= job.max_backlogs) &&
  job.branches.includes(student.branch) &&
  (new Date() < new Date(job.deadline))
2. State Machine Integrity Guard:

Prevents backwards status regressions and rejects withdrawals for candidates already in "selected" state with 400 Bad Request.

3. Standard Error Envelope:

All responses follow `{ success: boolean, message: string, data?: any }` to guarantee seamless client parsing.

Slide 11: Deployment & Engineering Challenges

SOLUTIONS APPLIED

Deployment Topology

Frontend Client SPA: http://localhost:5173 Vite 6 SPA with concurrent proxy configuration
Backend REST API: http://localhost:5000 Express server with native node:sqlite engine
GitHub Repository: campus_backend.git Unified full-stack repository with seed scripts

4 Critical Engineering Challenges & Solutions

1. C++ Addon Build Failures on SQLite:

Solution: Upgraded to Node 22 native node:sqlite module, completely bypassing node-gyp and python compiler errors.

2. Primary Key Drift During Database Re-seeding:

Solution: Eliminated hardcoded autoincrement IDs in the frontend; dynamically mapped entities by unique email and company name.

3. State Machine Terminal Status Corruption:

Solution: Enforced state machine validation blocking illegal status jumps (e.g. withdrawing already placed candidates).

4. High-Fidelity 1080p Demo Video Recording:

Solution: Piped Chrome DevTools Protocol screencast frames directly into FFmpeg H.264 encoder with animated cursor tracking.
